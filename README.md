# نظام الاستبيانات الورقية الموحّد

يجمع المشروع بين مساحة عمل عربية موحدة لتصميم الاستبيان، ومحرك توليد PDF وPNG، ومحرك OMR الأصلي لمعالجة الأوراق، وواجهتي مراجعة النتائج وتصديرها.

## بنية المشروع

```text
.
├── app.py                 # مدخل تشغيل النظام الموحد (Flask + OMR)
├── omr.py                 # محرك قراءة العلامات الأصلي
├── review.html            # واجهة مراجعة OMR الأصلية
├── survey.json            # الاستبيان التجريبي
├── requirements.txt       # متطلبات Python
├── package.json           # أوامر Node.js والاختبارات
├── server.js              # خادم مستقل لمحرر القالب
├── cli.js                 # أداة توليد القالب من سطر الأوامر
├── generator.js           # واجهة توافقية لوحدات التوليد
├── web/
│   ├── app.html           # الواجهة الرئيسية ذات التبويبات
│   ├── index.html         # واجهة تصميم القالب
│   ├── app.js             # إعدادات القالب والمعاينة والتوليد
│   └── app.css            # تنسيق واجهة المحرر
├── src/
│   ├── config.js          # أبعاد الصفحة والثوابت
│   ├── normalize.js       # توحيد بيانات الاستبيان والتحقق منها
│   ├── markup.js          # بناء HTML للاستبيان
│   ├── styles.css         # تنسيق الورقة المطبوعة
│   ├── pagination.js      # توزيع الأسئلة الكاملة على الصفحات
│   ├── coordinates.js     # إحداثيات الأسئلة ومناطق OMR
│   ├── chrome.js          # تشغيل Chromium عبر DevTools
│   └── export.js          # توليد المعاينة وPDF وPNG وlayout.json
├── tests/
│   ├── normalize.test.js  # اختبارات توحيد البيانات
│   ├── markup.test.js     # اختبارات HTML وتنسيق العناوين
│   ├── pagination.test.js # اختبارات منع تقسيم السؤال
│   ├── test_omr_unit.py   # اختبارات وحدات OMR
│   └── test_generated_template.py # اختبار PDF/PNG وتوافق OMR
└── docs/
    └── TEST_REPORT.md     # نطاق الاختبارات وحدودها
```

تبقى ملفات OMR وواجهة المراجعة المستقلة في الجذر حفاظاً على طريقة تشغيلها. واجهات النظام في `web/`، ومحرك بناء الورقة في `src/`.

## التشغيل الموصى به: النظام الموحد

يتطلب Python 3.10 أو أحدث، وNode.js 22 أو أحدث، ومتصفح Chrome أو Edge أو Chromium.

ثبّت متطلبات Python:

```bash
python -m pip install -r requirements.txt
```

من جذر المشروع شغّل:

```bash
python app.py
```

يفتح النظام الموحد على `http://127.0.0.1:5000`. يوفر هذا الوضع تصميم القالب ورفع الصور ومعالجة OMR والمراجعة والنتائج من واجهة واحدة.

## تشغيل محرر القالب مستقلاً (اختياري)

لتشغيل محرر PDF/PNG دون تبويبات OMR:

```bash
npm start
```

ثم افتح `http://127.0.0.1:4173`. هذا الوضع يخدم محرر القالب فقط، ولا يوفر واجهة رفع أوراق OMR والمراجعة.

## أوامر التطوير والاختبار

```bash
npm test
npm run test:python
python -m py_compile app.py omr.py
npm run generate
python -m unittest discover -s tests -p "test_generated_template.py" -v
```

لتوليد القالب من ملف المثال عبر Chromium:

```bash
npm run generate
```

يتطلب التوليد وجود Chrome أو Edge أو Chromium. ينشئ الملفات في `template/`. بعد التوليد يمكن تشغيل اختبار PDF/PNG والتوافق مع OMR بالأمر الأخير أعلاه.

## تجربة الاستخدام

الواجهة الرئيسية منظمة كتدفق من أربع مراحل: تصميم القالب، رفع الأوراق ومعالجتها، مراجعة الإجابات، ثم تصدير النتائج. يتكيف شريط التنقل مع الشاشات الصغيرة، وتظهر حالة القالب وعدد صفحاته وأسئلته قبل السماح ببدء المعالجة. يتطلب بدء دفعة جديدة تأكيداً لأن هذا الخيار يمسح بيانات المعالجة السابقة. كما لا تتاح روابط تنزيل CSV وJSON قبل وجود نتائج محفوظة.

## تبويبات النظام الموحد

- **تصميم القالب:** محرر مرئي للأسئلة يتيح الإضافة والحذف والنسخ وإعادة الترتيب، وتحرير نص السؤال بالعربية والإنجليزية، وتحديد نوعه وإدارة خياراته باللغتين. ويمكن أيضاً سحب مقبض السؤال مباشرة من المعاينة لتثبيت موضعه الدقيق على صفحة A4، بما في ذلك الهوامش خارج منطقة النص المعتادة. تُحفظ إحداثيات الصفحة والموضع والعرض في `print_position`، وتنعكس على PDF وPNG و`layout.json` حتى تتطابق إحداثيات OMR. يمكن إرجاع السؤال إلى التدفق التلقائي من زر ↶ في بطاقة السؤال. يمكن إضافة عنوان قسم لكل مجموعة من الأسئلة. يتوفر محرر JSON للتعديلات المتقدمة. كما يمكن تحرير عنوان الاستبيان وإظهاره أو إخفاؤه وضبط محاذاته ووزنه وحجمه، والتحكم بعناوين الأقسام والأسئلة والخيارات والهوامش. تنعكس الإعدادات على المعاينة وPDF وPNG وتحفظ ضمن `layout_settings`.
- **رفع ومعالجة:** رفع الصور أو ملفات PDF وتشغيل محرك OMR.
- **المراجعة:** عرض الصور والإجابات المكتشفة وتعديل الإجابات غير المؤكدة أو إدخال إجابات الأسئلة النصية يدوياً.
- **النتائج:** عرض الإجابات المحفوظة وتصديرها إلى CSV أو JSON.

## قاعدة تخطيط الأسئلة

يبقى كل سؤال مع جميع خياراته كتلة واحدة. لا يقسم محرك الصفحات السؤال بين صفحتين. إذا كان السؤال أطول من المساحة القابلة للطباعة في صفحة واحدة، يعرض المحرك رسالة تطلب تقليل محتواه بدلاً من تقسيمه.

## ملفات البيانات الناتجة

ينشئ البرنامج هذه المجلدات عند التشغيل:

- `template/`: ملفات PDF وPNG وHTML و`layout.json`.
- `work/`: الصور المحاذاة وبيانات الأوراق الممسوحة.
- `output/`: نتائج المراجعة المصدرة.
- `uploads/`: ملفات الرفع المؤقتة التي تحذف بعد المعالجة.

يحفظ آخر استبيان مولّد في `survey.current.json)، مع الاحتفاظ بملف المثال `survey.json`. الملفات الناتجة والمؤقتة مستثناة من Git.

## ثوابت يجب الحفاظ عليها

- لا تعدّل خوارزمية اكتشاف العلامات أو حساب درجات الحبر في `omr.py) ضمن أعمال تنظيم الواجهة.
- يجب حفظ PNG و`layout.json` الناتجين معاً؛ لأن محرك OMR يعتمد على الإحداثيات ومراكز علامات الزوايا.
- لا تغيّر أبعاد علامات الزوايا أو مواقعها أو بنية `layout.json` دون اختبار توافق OMR.
