# نظام الاستبيانات الورقية الموحّد

يجمع المشروع بين واجهة تصميم الاستبيان، ومحرك توليد PDF وPNG، ومحرك OMR الأصلي لمعالجة الأوراق، وواجهتي مراجعة النتائج وتصديرها.

## بنية المشروع

```text
.
├── app.py                 # نقطة تشغيل النظام الموحد وخادم Flask
├── omr.py                 # محرك قراءة العلامات الأصلي (يبقى دون تعديل)
├── review.html            # واجهة مراجعة OMR المستقلة
├── survey.json            # ملف استبيان تجريبي
├── requirements.txt       # متطلبات Python
├── web/
│   ├── app.html           # الواجهة الرئيسية ذات التبويبات
│   ├── index.html         # واجهة تصميم القالب
│   ├── app.js             # منطق إعدادات القالب والمعاينة والتوليد
│   └── app.css            # تنسيق واجهة تصميم القالب
├── src/
│   ├── config.js          # أبعاد الصفحة والثوابت
│   ├── normalize.js       # توحيد بيانات الاستبيان والتحقق منها
│   ├── markup.js          # بناء HTML للاستبيان
│   ├── styles.css         # CSS الخاص بالورقة المطبوعة
│   ├── pagination.js      # توزيع الأسئلة الكاملة على الصفحات
│   ├── coordinates.js     # جمع إحداثيات الأسئلة ومناطق OMR
│   ├── chrome.js          # تشغيل Chromium والتعامل معه
│   └── export.js          # المعاينة وتوليد PDF وPNG وlayout.json
└── docs/
    └── TEST_REPORT.md     # سجل نتائج الاختبارات الموثقة
```

تبقى ملفات `app.py` و`omr.py` و`review.html` في الجذر لأن تشغيل OMR المستقل يعتمد على وجود ملف المراجعة بجوار محركه. واجهات الموقع موجودة في `web/`، أما HTML/CSS والتخطيط والإحداثيات الخاصة بالقالب فهي في `src/`.

## التشغيل

يتطلب Python 3.10 أو أحدث، وNode.js 22 أو أحدث، ومتصفح Chrome أو Edge أو Chromium.

ثبّت متطلبات Python:

```bash
python -m pip install -r requirements.txt
```

ثم من جذر المشروع شغّل:

```bash
python app.py
```

يفتح البرنامج تلقائياً على:

```text
http://127.0.0.1:5000
```

هذا هو مدخل التشغيل الموحد. يتولى Flask تقديم الواجهات من `web/`، ويمرر طلبات إنشاء القالب إلى محرك JavaScript في `src/` عبر Node.js. وعند رفع الأوراق يستدعي `app.py` الدالة `omr.process()` من ملف `omr.py` الأصلي.

## تبويبات البرنامج

- **تصميم القالب:** ضبط حجم خط الأسئلة والخيارات، وحجم عنوان الاستبيان وعناوين الأقسام، وهوامش الصفحة، ووزن النص، وتسطير العناوين، وإظهار أو إخفاء الخطوط الفاصلة. تطبق الإعدادات على المعاينة وPDF وPNG وتحفظ ضمن `layout_settings`.
- **رفع ومعالجة:** رفع الصور أو ملفات PDF وتشغيل محرك OMR.
- **المراجعة:** عرض الصفحات والإجابات المكتشفة، وتعديل الإجابات غير المؤكدة أو إدخال إجابات الأسئلة النصية يدوياً.
- **النتائج:** عرض الإجابات المحفوظة وتصديرها إلى CSV أو JSON.

## قاعدة تخطيط الأسئلة

يبقى كل سؤال مع جميع خياراته كتلة واحدة. لا يقسم محرك الصفحات السؤال بين صفحتين. وإذا كان السؤال أطول من المساحة القابلة للطباعة في صفحة واحدة، يعرض المحرك رسالة تطلب تقليل محتواه بدلاً من تقسيمه.

## ملفات البيانات الناتجة

ينشئ البرنامج هذه المجلدات عند التشغيل:

- `template/`: ملفات `survey.pdf` و`p1.png` وغيرها و`layout.json`.
- `work/`: الصور المحاذاة وبيانات الأوراق الممسوحة.
- `output/`: نتائج المراجعة المصدرة.
- `uploads/`: ملفات الرفع المؤقتة، وتحذف بعد المعالجة.

كما يحفظ آخر استبيان مولّد في `survey.current.json` ويحتفظ بملف المثال `survey.json` دون استبداله. هذه الملفات والمجلدات التشغيلية مستثناة من Git عبر `.gitignore`.

## حدود الاختبار الحالية

يوثق `docs/TEST_REPORT.md` نتائج تحقق سابقة. لكن نسخة المستودع الحالية لا تحتوي على `package.json` أو ملف الاختبار `tests/test_omr_integration.py` المشار إليهما في التقرير؛ لذلك لا يمكن اعتبار أوامر الاختبار المذكورة فيه قابلة لإعادة التشغيل من هذه النسخة قبل إرجاع ملفات الاختبار إلى المستودع. يجب إجراء اختبار توليد بصري فعلي واختبار OMR على ملفات مولدة قبل اعتماد أي تغيير يمس التخطيط أو الإحداثيات.

## ثوابت يجب الحفاظ عليها

- لا تعدّل خوارزمية اكتشاف العلامات أو حساب درجات الحبر في `omr.py` ضمن أعمال تنظيم الواجهة.
- يجب حفظ PNG و`layout.json` الناتجين معاً؛ لأن محرك OMR يعتمد على إحداثيات الصور ومراكز علامات الزوايا والمستطيلات.
- لا تغيّر أبعاد علامات الزوايا أو مواقعها أو بنية `layout.json` دون اختبار توافق OMR.
