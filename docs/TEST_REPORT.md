# تقرير الاختبارات

## الاختبارات الآلية المضافة

تم إعداد الاختبارات التالية ضمن المستودع:

| الملف | ما يغطيه |
|---|---|
| `tests/normalize.test.js` | توحيد النصوص الثنائية اللغة، ربط الأسئلة بالأقسام، والتحقق من بنية الاستبيان |
| `tests/markup.test.js` | تهريب HTML، تمرير إعدادات الخطوط، استهداف الخطوط الفاصلة، وبقاء السؤال مع خياراته في كتلة واحدة |
| `tests/pagination.test.js` | منع تقسيم السؤال، وإبقاء عنوان القسم مع أول سؤال تحته |
| `tests/test_omr_unit.py` | قواعد قبول الإجابة، كشف تعدد العلامات، اكتشاف علامات الزوايا، وتهيئة سجل الورقة |

## تشغيل الاختبارات محلياً

من جذر المستودع:

```bash
npm test
npm run test:python
python -m py_compile app.py omr.py
```

يتطلب اختبار Python تثبيت NumPy وOpenCV، وهما ضمن متطلبات المشروع.

## التكامل المستمر

يحتوي `.github/workflows/ci.yml` على مسارين مستقلين:
- اختبارات JavaScript باستخدام Node.js 22.
- فحص صياغة Python وتشغيل اختبارات وحدات OMR باستخدام Python 3.11 وOpenCV headless.

يجب مراجعة نتيجة GitHub Actions للفرع قبل دمج طلب التحديث. لم يتم تسجيل نجاح الاختبارات في هذا التقرير قبل تشغيل الـ workflow على commit الاختبارات.

## الاختبارات التي لا تزال مطلوبة

الاختبارات الحالية وحدات مستقلة وليست بديلاً عن اختبار كامل على جهاز التشغيل. قبل اعتماد تغييرات التخطيط أو الإحداثيات يجب أيضاً:

1. توليد PDF وPNG من عينة قصيرة وأخرى متعددة الصفحات عبر Chrome أو Edge.
2. فحص الخطوط الفاصلة والأحجام والهوامش بصرياً في المعاينة وPDF.
3. مقارنة أبعاد PNG ومراكز علامات الزوايا ومناطق الخيارات مع `layout.json`.
4. طباعة عينة أو إنشاء صورة مسح تجريبية وتمريرها عبر `omr.py` للتحقق من ثبات قراءة الإجابات.
5. اختبار رفع PDF والصور من واجهة Flask ومراجعة النتائج المصدرة.

## الثوابت

- كل سؤال وخياراته وحدة واحدة ولا يتم تقسيمه بين الصفحات.
- `omr.py` يبقى كما هو ما لم يطلب المستخدم صراحة تعديله.
- أي تعديل في تخطيط الورقة يجب أن يحافظ على التطابق بين PNG و`layout.json`.
