## تفاصيل اختبار PDF وOMR

- تم التحقق من ترويسة PDF وصلاحيته الأساسية وحجم ملفه.
- تطابقت أبعاد كل PNG مع أبعاد الصفحة المقابلة في `layout.json`.
- تم فحص علامات الزوايا الأربع ومراكزها السوداء، والتحقق من وقوع مستطيلات الأسئلة داخل حدود الصفحة.
- أنشأ الاختبار علامة إجابة اصطناعية داخل الخيار الأول، ثم مرر الصورة إلى دالة `omr.process()` الأصلية.
- النتيجة: ورقة واحدة وصورة واحدة، **صفر أخطاء محاذاة**، واكتشاف الخيار الأول المحدد بالحالة `ok`.

ظهر تحذير Python غير مؤثر عن ملف `layout.json` المفتوح من كود OMR الأصلي. لم يُعدّل `omr.py` ضمن هذه المرحلة حفاظاً على المحرك الأصلي.

## التشغيل المحلي

```bash
npm test
npm run test:python
python -m py_compile app.py omr.py
npm run generate
python -m unittest discover -s tests -p "test_generated_template.py" -v
```

يتطلب توليد PDF وجود Node.js 22 أو أحدث ومتصفح Chrome أو Edge أو Chromium. تتطلب اختبارات Python NumPy وOpenCV.

## حدود الاختبار

اختبار OMR المتكامل يستخدم علامة اصطناعية مرسومة على صورة مولدة، وليس ورقة مطبوعة أو تصويراً بكاميرا/ماسح حقيقي. قبل الاعتماد النهائي في بيئة العمل، يجب إجراء تجربة طباعة ومسح فعلية وفحص PDF بصرياً.

## الثوابت

- كل سؤال وخياراته وحدة واحدة ولا يتم تقسيمه بين الصفحات.
- `omr.py` يبقى كما هو ما لم يطلب المستخدم صراحة تعديله.
- أي تعديل في تخطيط الورقة يجب أن يحافظ على التطابق بين PNG و`layout.json`.
