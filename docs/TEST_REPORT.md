# تقرير الاختبارات

## تغطية الواجهة وتجربة الاستخدام

أضيفت تغطية لاختبارات واجهة التطبيق في:

- `tests/ui.test.js`: التحقق من ثبات معرّفات عناصر التحكم، ترتيب خطوات تحرير الاستبيان (العنوان ثم الأسئلة ثم التنسيق)، وجود محرر الأسئلة المرئي، دعم CRUD وإعادة الترتيب والخيارات ثنائية اللغة، الحفاظ على بيانات تنسيق الأقسام، تنزيل ملف الاستبيان الأصلي JSON، تجاوب الشاشات، وصحة بناء JavaScript.
- `tests/test_ui_routes.py`: اختبارات Flask smoke لمساحة العمل الرئيسية، ومحرر القالب، وصفحة المراجعة وملفات CSS/JS ونقاط الحالة والنتائج.

## الاختبارات الآلية

| الملف | ما يغطيه |
|---|---|
| `tests/normalize.test.js` | توحيد النصوص الثنائية اللغة، ربط الأسئلة بالأقسام، والتحقق من بنية الاستبيان |
| `tests/markup.test.js` | تنسيق عنوان الاستبيان ومحاذاته وإخفاؤه، تهريب HTML، وخطوط العناوين |
| `tests/pagination.test.js` | منع تقسيم السؤال وإبقاء عنوان القسم مع أول سؤال تحته |
| `tests/ui.test.js` | الواجهة الموحدة، محرر الأسئلة المرئي، الترتيب المتجاوب، وحفظ مسار التصدير |
| `tests/test_ui_routes.py` | استجابات صفحات التطبيق ونقاط API الأساسية |
| `tests/test_omr_unit.py` | قواعد قبول الإجابة، كشف تعدد العلامات، اكتشاف علامات الزوايا، وتهيئة سجل الورقة |
| `tests/test_generated_template.py` | التحقق من PDF وPNG الناتجين، الإحداثيات وعلامات الزوايا، وقراءة إجابة اصطناعية عبر OMR الأصلي |

## تفاصيل اختبار PDF وOMR

- تم التحقق من ترويسة PDF وصلاحيته الأساسية وحجم ملفه.
- تطابقت أبعاد كل PNG مع أبعاد الصفحة المقابلة في `layout.json`.
- تم فحص علامات الزوايا الأربع ومراكزها السوداء، والتحقق من وقوع مستطيلات الأسئلة داخل حدود الصفحة.
- أنشأ الاختبار علامة إجابة اصطناعية داخل الخيار الأول، ثم مرر الصورة إلى دالة `omr.process()` الأصلية.
- النتيجة: ورقة واحدة وصورة واحدة، **صفر أخطاء محاذاة**، واكتشاف الخيار الأول المحدد بالحالة `ok`.

ظهر تحذير Python غير مؤثر عن ملف `layout.json` المفتوح من كود OMR الأصلي في بعض التشغيلات السابقة. لم يُعدّل `omr.py` حفاظاً على المحرك الأصلي.

## التشغيل المحلي

```bash
npm test
npm run test:python
python -m py_compile app.py omr.py
npm run generate
python -m unittest discover -s tests -p "test_generated_template.py" -v
python -m unittest discover -s tests -p "test_ui_routes.py" -v
```

يتطلب توليد PDF وجود Node.js 22 أو أحدث ومتصفح Chrome أو Edge أو Chromium. تتطلب اختبارات Python Flask وNumPy وOpenCV.

## حدود الاختبار

اختبار OMR المتكامل يستخدم علامة اصطناعية مرسومة على صورة مولدة، وليس ورقة مطبوعة أو تصويراً بكاميرا/ماسح حقيقي. كما أن اختبارات الواجهة الحالية تشمل فحوص DOM/الموارد والمسارات وبناء JavaScript؛ لا تغني عن اختبار استخدام بشري على أحجام شاشات ومتصفحات فعلية. قبل النشر العام، يجب إجراء تجربة طباعة ومسح فعلية ومراجعة صلاحيات الاستضافة وحماية الملفات والنسخ الاحتياطية وفق بيئة النشر.

## الثوابت

- كل سؤال وخياراته وحدة واحدة ولا يتم تقسيمه بين الصفحات.
- `omr.py` يبقى كما هو ما لم يطلب المستخدم صراحة تعديله.
- أي تعديل في تخطيط الورقة يجب أن يحافظ على التطابق بين PNG و`layout.json`.
